## 摘要

本项目完成了一个简化版在线问卷系统，覆盖账号、问卷管理、四种题型、条件跳转、填写校验、匿名与重复控制、统计查看等完整流程。系统使用 Python、Flask、PyMongo 和原生前端，业务数据全部存储在 MongoDB 中，没有使用关系数据库或现成问卷系统框架。

最终自动测试共 13 项，全部通过。测试使用真实 MongoDB 创建独立测试数据库，覆盖问卷创建与加题、单选/多选/数字跳转、必答与范围校验、服务端路径复核、提交幂等、重复填写控制、关闭后重新开放和聚合统计。浏览器验收覆盖登录、注册时间显示、问卷编辑、新题默认必答、跳转目标序号、问卷填写、提交成功和统计页面。

## 1. 项目目标与交付范围

项目的核心目标是验证 MongoDB 数据结构设计、后端业务建模、动态跳转和 AI 辅助开发的可用性。系统需要满足：

- 注册用户创建并管理自己的问卷。
- 通过 `/survey/<slug>` 链接分发问卷。
- 登录用户填写问卷，匿名问卷不在回答中保存用户 ID。
- 支持单选、多选、文本填空和数字填空。
- 跳转条件存储在问卷数据中，由通用解释器执行。
- 服务端重新校验答案和跳转路径。
- 创建者查看选项频数、文本内容和数字统计。
- 所有运行数据保存在 MongoDB。
- 项目可以启动、可以测试、文档完整。

第一阶段不包含邮件验证、找回密码、多人协作和回答文件导出。

## 2. 系统设计

### 2.1 总体架构

系统采用四层结构：

| 层次 | 主要职责 | 实现位置 |
| --- | --- | --- |
| 浏览器界面 | 登录、编辑、填写、查看统计 | `public/` |
| HTTP API | 认证、权限、状态转换、错误协议 | `app/routes.py`、`app/__init__.py` |
| 业务逻辑 | 题目校验、答案校验、跳转遍历、幂等提交 | `app/validation.py`、`app/security.py` |
| 数据层 | Schema、索引、持久化和聚合 | `app/schema.py`、MongoDB |

系统入口为 `server.py`。应用启动时幂等创建集合校验器和索引。

### 2.2 业务模块

账号模块保存用户名、标准化用户名、密码哈希和注册时间。密码使用 Werkzeug scrypt 哈希。会话保存在 MongoDB，Cookie 只保存随机令牌，数据库保存令牌的 SHA-256 哈希。

问卷模块保存所有者、标题、说明、公开 slug、发布状态、截止时间、匿名策略和重复填写策略。发布中的问卷不能修改题目；已有回答后题目保持锁定，但仍可修改说明和设置，并重新开放问卷。

填写模块一次展示一道题。浏览器根据答案计算下一步并即时提示错误；提交时服务端从第一题开始重新遍历，不能信任客户端给出的“下一题”或“已到达题目”。

统计模块使用 MongoDB 聚合管道展开答案数组，按题目分组后计算：

- 单选/多选选项次数和百分比。
- 文本题全部回答内容。
- 数字题平均值、最小值和最大值。

### 2.3 页面入口

| 页面 | 路径 | 功能 |
| --- | --- | --- |
| 登录/注册/问卷列表 | `/`、`/login`、`/register` | 展示账号注册时间，管理自己的问卷 |
| 问卷编辑器 | `/builder/<surveyId>` | 管理题目、校验和跳转 |
| 填写页 | `/survey/<slug>` | 登录后一次一题填写 |
| 统计页 | `/stats/<surveyId>` | 整卷与逐题筛选 |

## 3. MongoDB 设计

### 3.1 集合划分

| 集合 | 关键字段 | 设计目的 |
| --- | --- | --- |
| `users` | `usernameKey`、`passwordHash`、`createdAt` | 账号唯一性和密码安全 |
| `sessions` | `tokenHash`、`userId`、`expiresAt` | 登录会话和 TTL 清理 |
| `surveys` | `ownerId`、`slug`、`status`、`closesAt` | 问卷元数据与生命周期 |
| `questions` | `surveyId`、`id`、`type`、`options`、`validation`、`jumps` | 多态题目和条件跳转 |
| `submissions` | `surveyId`、`participantKey`、`answers`、`idempotencyKey` | 一次完整回答和统计来源 |

### 3.2 聚合边界

题目与问卷分开，因为题目需要独立顺序索引，并在发布前整体替换。选项、校验和跳转嵌入题目，因为它们的生命周期与题目一致，且每道题都有数量上限。

答案数组嵌入一次提交，因为一次填写必须作为整体保存。统计时使用 `$unwind` 展开 `submissions.answers`，无需跨集合拼接答案。

回答不重复保存问卷标题和题目全文，只保存稳定的题目 ID 和选项 ID。系统通过“发布中禁止改题、已有回答后禁止改题”保护历史统计。说明、设置和状态仍可更新，不改变已有答案含义。

### 3.3 索引

| 索引 | 作用 |
| --- | --- |
| `users.usernameKey` unique | 防止并发重复用户名 |
| `sessions.tokenHash` unique | 快速校验随机令牌 |
| `sessions.expiresAt` TTL | 删除过期会话 |
| `surveys.slug` unique | 保证公开链接唯一 |
| `surveys.ownerId + createdAt` | 用户问卷列表 |
| `questions.surveyId + order` unique | 题目顺序唯一 |
| `submissions.surveyId + submittedAt` | 回答时间查询 |
| `submissions.surveyId + participantKey` partial unique | 每人一次 |
| `submissions.surveyId + idempotencyKey` partial unique | 提交幂等 |

### 3.4 集合校验

`app/schema.py` 使用 MongoDB `$jsonSchema` 校验关键字段存在性和类型，并通过 `collMod` 应用到集合。应用启动时自动创建集合并更新校验器。

### 3.5 为什么适合 MongoDB

问卷题目是不同字段结构的多态对象，条件跳转是长度可变的嵌套数组，一次回答是天然的整体文档。MongoDB 允许这些结构直接建模，并通过索引和聚合管道支持主要查询。

关系数据库可以实现相同业务，但需要题目表、选项表、跳转条件表和答案明细表，读取和写入都要多次连接。本项目的聚合边界更贴合实际读写模式，因此选择 MongoDB。

## 4. 跳转设计

### 4.1 规则结构

每条规则由条件与目标题目 ID 组成：

```text
单选题：option_is + optionId
多选题：contains + optionId
数字题：eq/neq/gt/gte/lt/lte/between + value
```

目标题目只能位于当前题目之后。该限制消除跳转环路，保证问卷最终可以结束。

### 4.2 执行顺序

```text
current = 第一题
while current 存在:
    读取并校验当前答案
    如果有命中规则:
        进入第一条命中规则的目标
    else:
        进入下一题
```

被跳过的题目不执行必答校验。服务端完成遍历后，如果请求包含未到达题目的答案，会返回 `UNEXPECTED_ANSWER`，防止隐藏分支数据污染统计。

### 4.3 数据驱动

程序中没有某一份具体问卷的题目编号或选项文本分支。所有路径由 `questions.jumps` 数据决定，解释器位于 `app/validation.py`。

## 5. 校验设计

### 5.1 浏览器端

- 必答。
- 多选最少和最多选择数。
- 文本最少和最多字符数。
- 数字范围与整数。
- 返回上一题或改变分支时清理下游旧答案。

浏览器校验用于即时提示，不承担最终安全职责。

### 5.2 服务端

- 答案类型必须与题型一致。
- 单选和多选值必须属于题目选项。
- 多选不能重复选择同一选项。
- 文本去除首尾空白后检查长度。
- 数字必须有限，并满足范围和整数约束。
- 实际到达的必答题不能为空。
- 未到达题目的答案被拒绝。
- 跳转目标必须存在且位于当前题目之后。

### 5.3 数据库层

- JSON Schema 拒绝关键字段缺失和错误类型。
- 唯一索引处理并发注册、题目顺序、参与者去重和提交幂等。
- TTL 索引清理过期会话。

### 8.2 AI 使用说明

AI 帮助完成的主要工作：

- 把自然语言需求拆成账号、问卷、题目、回答和统计五个业务对象。
- 提出 MongoDB 集合划分、内嵌边界和主要索引。
- 生成 Flask API、原生前端、校验器和自动化测试初稿。
- 用真实 MongoDB 和浏览器执行验收，定位并修复 `NaN`、关闭后无法重发、预览链接错误等问题。
- 整理系统、数据库、API、逻辑、测试和报告文档。

AI 出现的错误：

- 最初选择了当前环境无法安装依赖的 Node.js 方案，项目不可运行。
- 新题没有同步 `order`，跳转目标显示 `第NaN题`。
- 保存关闭问卷时无条件保存题目，被历史回答保护规则阻断。
- 预览按钮一度指向 `#`。
- 两项单元测试的路径前提错误，把实际到达的题目误认为被跳过题目。
- 注册时间 CLI 初次运行存在模块导入和 Windows 控制台编码问题。

项目负责人通过实际验收提出并确认的修改：

- 注册时间需要可见，并提供后端查询方式。
- 跳转目标序号必须正确。
- 已有回答的关闭问卷必须可以重新开放。
- 新建题目默认必答。

最终版在 AI 初稿上完成的设计与实现调整：

- 只允许向后跳转，避免循环。
- 浏览器校验和服务端校验分离，服务端重新遍历完整路径。
- 已有回答后锁定题目，但允许修改说明和设置。
- 匿名与“一人一次”通过 HMAC 技术键兼容，不保存匿名回答的用户 ID。
- 幂等键与 MongoDB 部分唯一索引共同处理双击和网络重试。

本报告不把 AI 自动生成的初稿描述为人工独立编写，也不把未运行的测试描述为通过。人工反馈、AI 修改、执行结果和剩余限制分别记录。

## 9. 遇到的问题与解决

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| Node 方案不能运行 | 当前环境无法联网安装依赖 | 改用 Flask + PyMongo，删除未运行草稿 |
| 跳转可能形成环 | 目标题目允许任意方向 | 强制目标位于当前题目之后 |
| 修改题目导致历史统计失真 | 旧答案引用已删除题目或选项 | 发布中和已有回答后锁定题目 |
| 匿名与去重冲突 | 保存用户 ID 会破坏匿名目标 | 保存 HMAC 去重键，不保存匿名用户 ID |
| 并发重复提交 | 应用层查询存在并发窗口 | 数据库部分唯一索引兜底 |
| 双击或网络重试 | 浏览器可能重复发送相同请求 | 幂等键和唯一索引 |
| `第NaN题` | 新题没有同步 `order` | 渲染和保存前统一重建顺序 |
| 关闭后无法重发 | 保存设置时无条件保存题目 | 设置与题目分开保存，使用 `hasResponses` 判断 |
| 注册时间不可见 | 页面没有使用已有 `createdAt` | 首页展示，并提供 CLI 查询 |
